How do I access a file with an URL-encoded name on a LocalStore?
I'm trying to read a file `/foo/hello%20world.txt` on my local disk. However, no matter how I format the url, [LIB] never actually finds the file.

```python
import [LIB].store
store = [LIB].store.from_url("file://")
result = [LIB].get(store, "/foo/hello%20world.txt")

>>> FileNotFoundError: Object at location /foo/hello%2520world.txt not found: No such file or directory (os error 2)
```

So it seems like in this case, the file name is URL-encoded again before the local file system is accessed.
However, trying to decode the `%20` before calling [LIB] also does not work:

```python
import [LIB].store
store = [LIB].store.from_url("file://")
result = [LIB].get(store, "/foo/hello world.txt")

>>> FileNotFoundError: Object at location /foo/hello world.txt not found: No such file or directory (os error 2)
```

In that case (no special characters present), [LIB] doesn't do anything to the filename, which leave the (literal) filename `hello%20world.txt` completely unaccessible.

Any advice on how to make this work apart from double-encoding all files containing special URL characters?
Hmm it's possible we may need to add a new API for this that wraps the upstream `Path::parse`:  

We currently always use [`Path::from(String)`](  which will always re-encode the string.
I wouldn't have a problem with re-encoding as long as it's consistent - I would just decode my filenames before calling `[LIB]`. The root of the problem seems to be the handling of the space character - it's an unsafe character according to RFC 1738 and thus I would expect it to behave the same as a `%` character. 

But:

`[LIB].get(store, "/a b")` tries to open `/a b` on disk  
`[LIB].get(store, "/a%b")` tries to open `/a%25b` on disk

But local file paths can have spaces in their name, so it seems to make sense that `[LIB]` allows that.

I think the best way to solve this would be to export a `Path` class. 99% of users will never have to touch it, but for these url-encoded names you can pass in `Path.parse(string)` to [LIB] APIs
