```

      **kwargs,
  )
```

I checked by s3 bucket from the dashboard and the directory does still exists, while its content does not. The [documentation ](  says that:

Don't remove trailing `/` with `split_path`. Keys with a trailing `/` are now properly removed.
`[LIB]` and `[LIB]` currently remove trailing `/` from a path while a S3 object key ending with a `/` is a valid key.
This causes problems when using `S3FileSystem.rm_file()` or `S3FileSystem.rm(path, recursive=True)` with keys that end with a `/`. 

There are 3 different places where this behaviour could be fixed:
1. The problem starts in `AbstractFileSystem._strip_protocol()` from `[LIB]` where all trailing `/`s are removed using `rstrip("/")`.
2. `AbstractFileSystem._strip_protocol()` is used by `S3FileSystem.split_path()` to get the bucket, key and version_id from an S3 path.
3. `S3FileSystem.rm_file()` and `S3FileSystem.rm()` use `S3FileSystem.split_path()` to get the key which will be deleted with `boto3`.

I have tried creating a custom version of `_strip_protocol` for `S3FileSystem` that doesn't delete the trailing `/` but this seems to break many of the `S3FileSystem` functions. `glob` being one for example. I have decided not the implement the fix in `_strip_protocol` for that reason. Handling keys with a trailing `/` complicated topic which has been discussed before in these issues:      and   

I think fixing it in `S3FileSystem.split_path()` is the correct choice for the following reasons:
1. `split_path` already doesn't remove the trailing `/` if the path contains a `version_id`. For example passing `"s3://mybucket/path/to/versioned_object/?versionId=some_version_id"` to `split_path` would not remove the trailing `/` from the key. My fix makes the behaviour consistent to now also keep the trailing `/` when there is no `version_id` in the path. If anything breaks because of my fix it would also have broken if it was a versioned object.
2. If we would not want the key to have a trailing `/` it should be removed after `split_path`. `split_path` should not change valid keys into non existing keys. If a function calls `split_path` and doesn't want a trailing `/` in the key for any reason then it should call `rstrip("/")` on the key. If my fix breaks any function we should add an `rstrip("/")` inside that function.

I have verified that the following examples now work correctly where they didn't before.

```python
import [LIB]
import boto3

bucket = "my-bucket"

client = boto3.client("s3")
fs = [LIB].S3FileSystem()

def create_test_keys():
    client.put_object(Bucket=bucket, Key="test/", Body=b"")
    client.put_object(Bucket=bucket, Key="test///", Body=b"")
    client.put_object(Bucket=bucket, Key="test/nested/", Body=b"")

create_test_keys()
print(fs.glob(f"s3://{bucket}/test/**"))

# Delete key with single trailing /
fs.rm_file(f"s3://{bucket}/test/")
print(fs.glob(f"s3://{bucket}/test/**"))

# Delete key with multiple trailing /
fs.rm_file(f"s3://{bucket}/test///")
print(fs.glob(f"s3://{bucket}/test/**"))

create_test_keys()
# Delete a "directory" containing keys with trailing /
fs.rm(f"s3://{bucket}/test/", recursive=True)
print(fs.glob(f"s3://{bucket}/test/**"))
```

`split_path` is used in many places across `S3FileSystem` and I have not yet checked if some function might be broken because of this change. I do believe that if a function breaks because of this we should change the behaviour in the broken function.
